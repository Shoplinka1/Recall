RECALL — FIX FIRST-USER SUBJECT CREATION BLOCKER

Continue from origin/main. The latest commit is 24d0b81.

Do NOT reset, rollback, or discard existing work.

We found a likely real-user blocker in Add Study Material:

A brand-new user may have NO existing subjects.

The current UI appears to require choosing an existing subject, but does not provide a clear way to CREATE a subject from the Add Study Material flow.

This can leave:
- no subject available to select
- Add to Recall disabled
- no clear explanation of what the user must do
- first-time users unable to add their first material

Fix the REAL cause.

FIRST-USER FLOW MUST WORK:

New account
→ Add Study Material
→ enter/paste material
→ choose an existing subject OR create a new subject
→ subject is persisted for the authenticated user
→ Add to Recall becomes enabled
→ submit
→ real upload/processing
→ material becomes READY
→ sections/concepts persist
→ material appears in library
→ user can build a study session

SUBJECT UX

If the user has no subjects:
- clearly show that a subject is required
- provide an obvious "Create subject" action
- allow the user to enter a subject name
- validate empty/invalid subject names
- create the subject through the real authenticated API
- associate it with the current authenticated user only
- automatically select the newly created subject
- then enable Add to Recall when the rest of the material form is valid

If subjects already exist:
- allow selecting an existing subject
- still provide a clear way to create another subject
