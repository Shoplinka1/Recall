13. PAYSTACK CHECKOUT FLOW
============================================================

Flow:

User clicks:

"Start Recall Pro"

↓

Frontend calls:

POST /api/payments/paystack/initialize

with:

monthly

or

annual

↓

Server:

1. Authenticates user.
2. Determines correct plan code.
3. Uses authenticated user's email.
4. Initializes Paystack transaction/subscription.
5. Stores appropriate pending transaction information.
6. Returns Paystack authorization URL.

↓

Frontend redirects to Paystack.

↓

User completes payment.

↓

Paystack redirects to Recall.

↓

Recall verifies the transaction SERVER-SIDE.

↓

Recall updates local subscription state only after successful verification.

NEVER activate Pro because:

- frontend says payment succeeded
- localStorage says Pro
- query parameter says success
- browser redirect occurred
- client-side state says paid

Only trusted server-side Paystack verification/webhook information may activate Pro.
